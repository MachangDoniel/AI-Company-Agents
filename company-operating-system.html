Operating system

Company Operating System

A lightweight delivery model for focused AI agents working like a software company, with Small Project Mode as the default.

Default behavior: if the user does not mention a mode, start in Small Project Mode. If the task appears broader than a focused change, the Lead asks which mode to use before implementation starts.

Small Project Mode

Use Lead, one Specialist Developer, and QA. This is the default for day-to-day work and keeps token cost lower.

  1. Lead intake and plan
  2. Specialist Developer implementation
  3. Lead review
  4. QA verification
  5. Logged closeout

Full Company Mode

Use the broader workflow for releases, production-sensitive work, unclear product scope, or cross-system projects.

  1. Manager intake
  2. Product definition
  3. Technical design
  4. Specialist implementation
  5. Security, QA, and release gates

Principles

  • One owner per phase.
  • Written handoffs before work changes hands.
  • Specialists join only when their domain matters.
  • QA verifies behavior, not intentions.
  • Security participates early for sensitive changes.
  • Release readiness is separate from implementation completion.

Full Lifecycle

  1. Intake by Manager
  2. Product definition by Product Owner
  3. Technical design by Tech Lead
  4. Implementation by Specialist Developer
  5. Security review when needed
  6. QA verification
  7. Release readiness
  8. Manager closeout
